name: Direct communication preference
description: User prefers direct communication over creative workarounds. If an implementation doesn't make sense with the current approach and needs a refactor or backend changes, tell them directly instead of trying strange solutions that cause long-term code problems.
type: feedback
---

When something isn't feasible: say so directly. Don't over-engineer workarounds that create technical debt or fragile code. Better to surface the real issue and let the user decide the path forward (e.g., backend fix, scope change, alternative approach).
